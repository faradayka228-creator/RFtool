## Сборка APK через GitHub Actions (без ПК, без локальной IDE)

Если AIDE на телефоне глючит — собери APK в облаке:

1. Зайди на github.com через браузер телефона (или приложение GitHub), залогинься / зарегистрируйся
2. Создай новый репозиторий: "+" → "New repository" → назови например `RFTool` → Create
3. На странице пустого репозитория нажми "uploading an existing file"
4. Загрузи **все файлы и папки** из распакованного `RFTool.zip` (включая скрытую папку `.github` — в мобильном браузере иногда её не видно в выборе файлов; если `.github/workflows/build.yml` не загрузился, создай его вручную через "Add file → Create new file" и вставь путь `/.github/workflows/build.yml` + содержимое из архива)
5. Commit changes
6. Перейди во вкладку **Actions** вверху репозитория — там автоматически начнётся сборка (или нажми "Run workflow" если не началась)
7. Через 2–5 минут внизу запуска появится раздел **Artifacts** → `RFTool-debug-apk` → скачай, это и есть твой `.apk`
8. Установи скачанный APK на телефон (разреши "установку из неизвестных источников" при первом разе)

## Как импортировать в AIDE
1. Распакуйте архив `RFTool.zip` в `Внутреннее хранилище/AppProjects/` (стандартная папка AIDE для проектов).
2. Откройте AIDE → "Открыть проект" → выберите папку `RFTool`.
3. AIDE автоматически обнаружит `build.gradle` и предложит синхронизацию зависимостей — подтвердите (нужен интернет при первой сборке для скачивания AndroidX/Material).
4. Соберите через меню "Run" ▶ или сочетание в AIDE.

## Что реализовано
- **BLE-сканер** — пассивное обнаружение устройств, оценка дистанции по RSSI (path-loss формула), вывод на радар.
- **Wi-Fi Wardriving** — фоновый `Service` с GPS-привязкой, агрегация SSID/BSSID/RSSI, экспорт в CSV (`wardrivingService.exportCsv()`).
- **LAN Topology Mapper** — асинхронный ping sweep подсети (`InetAddress.isReachable`), попытка резолва MAC через `/proc/net/arp` + мини-база OUI вендоров.
- **TCP Port Scanner** — многопоточный сканер диапазона портов с таймаутами, для аудита firewall в своей сети.
- **HCE (NFC)** — кастомный AID `F0010203040506` (НЕ платёжная карта), логирование APDU-обмена в терминал.
- **RadarView + Terminal Log** — кастомная `View` с анимацией развёртки, RecyclerView-терминал с цветовой кодировкой `[INFO]/[METRIC]/[BROADCAST]/[ERROR]`.

## Новые фичи (пентест-аудит + тонкая настройка UI)
- **Wi-Fi Security Auditor** — классификация шифрования сети (OPEN/WEP/WPA/WPA2/WPA3/OWE/Enterprise) + риск-метка (КРИТИЧНО/ВЫСОКИЙ/СРЕДНИЙ/НИЗКИЙ) в каждой строке лога Wi-Fi.
- **Wi-Fi Channel Analyzer** — после остановки Wardriving-сессии выводит рекомендованный наименее загруженный канал из непересекающихся 1/6/11 (2.4 ГГц).
- **BLE Manufacturer Decoder** — определяет вендора устройства по Company ID (Apple/Google/Samsung/Xiaomi/Microsoft и др.), распознаёт Fast Pair/Eddystone/iBeacon по сервисным UUID.
- **Signal Heatmap** — вторая визуализация (кнопка HEATMAP над радаром), показывает накопленные Wi-Fi точки относительно GPS-трека, цвет = сила сигнала.
- **Настройки (шестерёнка вверху экрана):**
  - Акцентный цвет радара (5 пресетов)
  - Скорость развёртки радара (500–6000 мс/оборот)
  - Плотность колец сетки (2–8)
  - Единицы измерения дистанции (метры/футы)
  - Виброотклик при обнаружении нового устройства
  - Автоскролл терминального лога
  - Фильтр уровня логов (всё / без INFO / только WARN+ERROR)

Все перечисленные фичи — исключительно пассивный разбор/классификация публично транслируемых данных (то же самое видит обычный телефон при поиске сетей/устройств). Никакого воздействия на чужие устройства/сети они не производят.

## Что осознанно НЕ реализовано
- Извлечение данных (PAN/срок действия) с платёжных EMV-карт через NFC — это функциональность скимминга.
- Массовая рассылка BLE advertising-пакетов на чужие устройства (имитация Fast Pair handshake и т.п.) — это DoS/спам-атака на чужие телефоны, а не диагностика своей сети.

## Разрешения, которые нужно будет подтвердить при первом запуске
Локация (для Wi-Fi/BLE сканов по требованию Android), Bluetooth (SCAN/CONNECT на Android 12+), уведомления (для foreground-сервиса).

## Известные нюансы
- `WifiManager.startScan()` на Android 9+ троттлится системой (не чаще ~4 раз за 2 минуты) — это ограничение ОС, не баг кода.
- Чтение `/proc/net/arp` может быть недоступно на некоторых прошивках/ядрах — в этом случае MAC будет помечен как `unknown`, остальной функционал не пострадает.
- `isReachable()` иногда не проходит через ICMP при отсутствии root — в коде это штатно обрабатывается как "хост недостижим".
